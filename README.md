# Осмотр квартиры

Веб-приложение для фиксации состояния квартиры при осмотре. Пользователь создаёт документ, описывает комнаты и дефекты, добавляет фотографии и получает PDF. Интерфейс на русском языке, адаптирован для телефона и компьютера.

В MVP используется демонстрационный вход: номер `70000000000` и код `0000` уже заполнены, SMS не отправляется. Каждый браузер получает отдельную случайную серверную сессию. Документы и сжатые фото хранятся в IndexedDB; фотографии дополнительно сохраняются в закрытой папке сервера. PDF формируется на устройстве. Оплаты в MVP нет.

## Реализованные возможности

- Библиотека осмотров: создание, открытие, переименование и удаление документов.
- Обязательные адрес и дата осмотра; необязательные название и описание.
- Комнаты типов «Коридор», «Кухня», «Комната», «Санузел», «Балкон», «Общее»; собственные названия, изменение типа и удаление.
- Шесть наборов по шесть пунктов проверки с подсказками для съёмки. Общеквартирные и комнатные отметки сохраняются независимо.
- Фото с камеры или из галереи, множественный выбор, подписи, просмотр и удаление.
- Дефекты с обязательным названием, описанием и отдельными фотографиями.
- Автосохранение, восстановление после перезагрузки, обработка нехватки места и конфликтов между вкладками.
- Предпросмотр и скачивание PDF; передача того же файла через системное меню, если браузер поддерживает Web Share для файлов.
- Полная самостоятельная копия документа с комнатами, отметками, дефектами и фото.

Основной сценарий: **демовход → новый документ → адрес и дата → комнаты → отметки, фото и дефекты → PDF**.

## Данные и фотографии

Сохранение считается успешным после завершения транзакции IndexedDB. При конфликте версий другая вкладка не перезаписывает изменения автоматически; доступно перечитывание с подтверждением. При ошибке записи введённые данные остаются в открытом сеансе для повторной попытки.

Изображения обрабатываются последовательно и повторно кодируются в JPEG с длинной стороной до 1600 px. Исходные EXIF и геометки не сохраняются. Лимиты: до 15 фото комнаты и до 6 фото каждого дефекта. Если выбранный набор превышает лимит, он отклоняется целиком.

На сервер отправляются только обработанные JPEG. Задания загрузки и удаления записываются в очередь IndexedDB в одной транзакции с изменением документа. Сбой сети не удаляет локальные данные: интерфейс показывает ошибку и кнопку повтора. Удаление фото, комнаты или документа ставит удаление серверных фото в ту же очередь; при отсутствии сети оно завершится после успешного повтора. Копия документа получает собственные ID фотографий.

Сервер хранит файлы вне каталога сайта, проверяет сессию и Origin, размер и структуру JPEG. Имена формируются из UUID; публичной папки загрузок нет. Версии и записи об удалении не позволяют запоздавшему запросу вернуть удалённое фото. Полные документы, тексты и PDF на сервер не отправляются. Шрифты и иллюстрации поставляются с приложением; внешней аналитики нет. Импорт сторонних PDF/DOCX не предусмотрен.

Документы привязаны к браузеру, устройству и origin сайта. Облачного восстановления документов нет. Очистка данных браузера удаляет локальные осмотры; смена домена, протокола или порта открывает другое хранилище. Потеря cookie лишает доступа к прежней серверной папке: общий тестовый номер не восстанавливает её. Для сохранения результата нужно скачать PDF. Закрытие вкладки до подтверждения записи может привести к потере последних изменений.

## PDF и ссылка на сайт

PDF формируется в формате A4 со встроенными кириллическими шрифтами. В него включаются адрес, дата осмотра, описания, комнаты, дефекты, фотографии с подписями и сноска. Контрольные отметки и подсказки в PDF не включаются.

Для большого документа изображения дополнительно сжимаются в экспортной копии; исходный осмотр и сохранённые фото не изменяются. Во время формирования отображаются реальные этапы обработки, при ошибке доступен повтор.

Кликабельная ссылка и QR-код в конце PDF ведут на один адрес из отдельного файла `site-config.json`:

```json
{
  "publicSiteUrl": ""
}
```

До сборки файл находится в `public/site-config.json`, после сборки и на сервере — в `dist/site-config.json`. После развёртывания достаточно указать полный HTTP(S) адрес в опубликованном файле: он читается без кэша перед каждым экспортом, пересборка не нужна. Настройка действует на новые PDF, ранее скачанные файлы не изменяются.

При пустом значении блок ссылки и QR отсутствует; текущий адрес браузера автоматически не подставляется. QR создаётся локально, данные осмотра в ссылку не добавляются. Если файл отсутствует с HTTP 404, для совместимости используется `VITE_PUBLIC_SITE_URL`; явно пустой файл отключает блок. Чтобы ссылка на распечатке оставалась рабочей, нужно сохранять домен и путь либо поддерживать перенаправление при переезде сайта.

## Локальный запуск

Требуется Node.js 20.17 или совместимая версия.

```sh
npm ci
npm run dev
```

`npm run dev` запускает интерфейс и локальный API фотографий. `npm run build` проверяет типы, создаёт клиент в `dist/` и сервер в `server-dist/`. `npm start` запускает собранное приложение на `http://127.0.0.1:8080`. `npm run preview` предназначен для локальной проверки клиентской сборки с тем же API.

## Проверки

```sh
npm test
npx playwright install chromium
npm run test:e2e
```

На Windows основной набор автоматически использует установленный Chrome, если он доступен. Другой Chromium задаётся через `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`. Тесты работают с изолированными профилями и синтетическими осмотрами. Основные регрессии выполняют настоящий API-демовход через fixture; отдельные `demo-access.spec.ts` и `server-photos.spec.ts` проверяют показанную пользователю форму, изоляцию сессий, серверные байты, сбой и повтор отправки.

Для проверки собранного приложения в PowerShell:

```powershell
npm run build
$env:QA_BUILT_APP = '1'
$env:QA_PREVIEW_BASE_URL = 'http://127.0.0.1:4173'
npm run test:e2e
Remove-Item Env:QA_BUILT_APP, Env:QA_PREVIEW_BASE_URL
```

Порт 4173 должен быть свободен. Дополнительная Windows-матрица использует установленный Edge и управляемые Firefox/WebKit:

```sh
npx playwright install firefox webkit
npx playwright test --config tests/e2e/crossbrowser.config.ts
```

Пути к установленным браузерам находятся в конфигурациях тестов. WebKit использует временный постоянный профиль для Blob в IndexedDB. В Edge 158 остаётся ограничение тестового наблюдателя: выполнение диагностики во вложенном `about:blank` встроенного PDF-просмотра может зависать после скачивания. Этот сценарий не считается полностью пройденным.

Лабораторный замер первого экрана: после сборки выполнить `node tests/e2e/firstscreen-lab.mjs`. Профиль: три открытия с пустым кэшем, 4 Мбит/с на загрузку, 1 Мбит/с на отправку и задержка 150 мс; HTTP-настройки берутся из `nginx.example.conf`. Первый экран теперь — заполненная форма демовхода. Замер не сопоставим напрямую с прежним экраном библиотеки.

Автоматизация проверяет сохранение, конфликты и ошибки хранилища, обработку фото, содержимое PDF, распознавание QR, копирование и отправку файла. Подстановка файла в тестах не заменяет физическую камеру; Web Share проверяется с подменой API. Реальные iPhone Safari/Android, системное меню отправки, экранная клавиатура и мобильная сеть требуют проверки на устройствах.

## Развёртывание

Нужны Node.js и один процесс приложения, запущенный через `npm start`, а также HTTPS reverse proxy. Каталоги `dist/` и `server-dist/` создаются сборкой. Dev/preview-сервер не предназначен для production. База данных сервера не требуется: фото и служебные записи хранятся в файлах.

Переменные окружения серверного процесса:

| Переменная | Значение |
| --- | --- |
| `NODE_ENV` | `production` на сервере |
| `APP_ORIGIN` | Обязательный для production HTTPS origin без пути, например `https://inspection.example.com` |
| `HOST` | По умолчанию `127.0.0.1`; API доступен через reverse proxy |
| `PORT` | По умолчанию `8080` |
| `PHOTO_DATA_DIR` | Закрытый каталог вне `dist/` и `public/`, по умолчанию `private-data/` |

Пример nginx находится в `nginx.example.conf`: клиент раздаётся из `dist`, запросы `/api/` передаются Node-процессу. Для production задаются фактические домен и TLS-сертификаты. Приватный каталог не подключается к nginx и не публикуется. Запускать несколько Node-процессов с общим каталогом данных нельзя: упорядочивание файловых операций выполняется внутри одного процесса.

Демонстрационные ограничения: до 5 МиБ на JPEG, 256 МиБ фото на браузерную сессию, 2 ГиБ суммарно, 500 различных ID фото за срок сессии, включая удалённые ID, и до 1000 сохранённых сессий. Автоматической очистки старых сессий нет; перед расширением публичного использования нужен отдельный порядок хранения и удаления данных. Демовход не подтверждает личность или владение номером телефона.

В nginx настроены защитные заголовки, CSP, правила кэширования и gzip для кода, стилей и шрифтов. PNG/JPEG передаются без дополнительного gzip. Для камеры требуется HTTPS; localhost разрешён для разработки.

После развёртывания проверить сохранение и перезагрузку, камеру/галерею, предпросмотр и скачивание PDF, кликабельную ссылку и сканирование QR с распечатки.
